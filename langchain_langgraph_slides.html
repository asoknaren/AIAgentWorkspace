Orchestration runtime: explicit state, nodes, edges, checkpoints, and replay for custom workflows.

What Is an AI Agent?

  • An LLM that decides what to do next and acts through tools, observing results until the task is done.
  • Core loop: Reason → Act (tool call) → Observe → Repeat → Answer
User request
→
LLM decides
→
Tool executes
→
LLM reads result
→
Final answer

Model

The reasoning engine (e.g. gpt-4o).

Tools

Functions that reach data and the outside world.

State / Memory

What the agent knows across steps and turns.

LangChain vs LangGraph

LangChainLangGraph
PurposeComponents & high-level agent APILow-level stateful orchestration
Key APIChatOpenAI, @tool, create_agentStateGraph, nodes, edges, checkpointers
Control flowModel decides (tool loop)You decide (routing, loops, parallel)
PersistenceVia a checkpointer passed to create_agentNative: checkpoints, threads, replay

Not competitors: create_agent returns a compiled LangGraph graph.

1 · Models, Messages & Streaming

from langchain_openai import ChatOpenAI
from langchain_core.messages import (
    SystemMessage, HumanMessage)

llm = ChatOpenAI(model="gpt-4o")

# single call
reply = llm.invoke("What does an agent do?")

# streaming tokens
for chunk in llm.stream("Write a poem"):
    print(chunk.content, end="")

# message roles
llm.invoke([
  SystemMessage("Answer in five words."),
  HumanMessage("Capital of France?")])

invoke

One request, one full response.

stream

Yields chunks as they are generated — responsive UIs.

Messages

SystemMessage sets behavior, HumanMessage is user input, AIMessage is the reply, ToolMessage carries tool results.

2 · Tools: Giving the Model Hands

from langchain_core.tools import tool

@tool
def get_share_price(symbol: str) -> float:
    """Return the current sample share price for a ticker symbol."""
    return {"AAPL": 241.5}.get(symbol.upper(), 0.0)

get_share_price.name         # 'get_share_price'
get_share_price.description  # from the docstring
get_share_price.args         # JSON schema from type hints
get_share_price.invoke({"symbol": "AAPL"})
  • LangChain builds the JSON Schema from type hints + docstring — write both carefully; the model reads them.
  • A tool is just a function the model may request; your code executes it.

5 · create_agent: The Prebuilt Agent Loop

from langchain.agents import create_agent

agent = create_agent(
    model="openai:gpt-4o",
    tools=[get_weather, get_population],
    system_prompt="You are a concise travel assistant.",
)
result = agent.invoke({"messages": [("user", "Compare Rome and London.")]})
print(result["messages"][-1].content)

You provide

Model, tools, system prompt.

It manages

Model call → tool calls (possibly parallel) → results back to model → final answer.

Inspect it: agent.get_graph().draw_mermaid() — it is a LangGraph graph (model node ⇄ tools node).

6 · Middleware: Hooks Around the Loop

from langchain.agents.middleware import wrap_tool_call

@wrap_tool_call
def log_tool_call(request, handler):
    call = request.tool_call
    print(f"[wrap_tool_call] {call['name']}({call['args']})")
    return handler(request)       # continue normally

agent = create_agent(model=..., tools=tools,
                     middleware=[log_tool_call])
  • Middleware wraps steps of the agent: observe, modify, retry, block, or short-circuit.
  • Typical uses: logging, guardrails, error handling, approval gates, rate limiting.

8 · LangGraph Core: State, Nodes, Edges

State

Shared data flowing through the graph (TypedDict).

Nodes

Functions that read state and return a partial update.

Edges

Decide what runs next. START / END mark boundaries.

builder = StateGraph(LessonState)            # 1-2 schema + builder
builder.add_node("prepare", prepare_node)       # 3 nodes
builder.add_edge(START, "prepare")              # 4 edges
builder.add_edge("prepare", END)
graph = builder.compile()                      # 5 compile
graph.invoke({"request": "hello"})                # 6 run

A node returns only what it changes: {"research_a": "..."} — LangGraph merges it into state.

9 · Reducers: Replace or Combine

class GraphState(TypedDict):
    # merges new messages into history
    messages: Annotated[list[AnyMessage],
                        add_messages]
    # appends each node's notes
    node_history: Annotated[list[str],
                            operator.add]
    # no reducer: newest value wins
    summary: str

No reducer

Update replaces the value (summary, reply).

With reducer

Update is combined: operator.add appends lists; add_messages merges chat history.

Why it matters

Parallel nodes writing the same field in one superstep are merged safely by the reducer.

10 · Conditional Edges & the Tool Loop

START
→
chatbot
→
tools_condition
→ tool calls →
tools
↩ chatbot

no tool calls → END

builder.add_conditional_edges("chatbot", tools_condition,
                              {"tools": "tools", END: END})
builder.add_edge("tools", "chatbot")       # loop back
  • Conditional edge: a function reads state and returns the next node.
  • Loop: route an edge back to an earlier node — this is the agent loop, built by hand.
  • ToolNode and tools_condition are prebuilt helpers for tool execution and routing.

14 · Memory: Checkpointers & Threads

graph = builder.compile(checkpointer=MemorySaver())
config = {"configurable": {"thread_id": "memory-demo"}}

graph.invoke({"message": "My favorite color is blue."}, config)
graph.invoke({"message": "I also like hiking."},   config)
# reply: "I remember 2 message(s): ...blue; ...hiking"

Checkpointer

Saves a state snapshot after every step.

thread_id

Identifies a conversation. Same ID = restored memory; new ID = fresh start.

On a resumed thread, send only new input. Resending a reducer field (e.g. a list with operator.add) would append it twice.

16 · Checkpoint History & Time Travel

history = list(graph.get_state_history(config))   # newest first
for snap in reversed(history):
    print(snap.metadata["step"], snap.next, snap.values)

# replay from an earlier checkpoint
past = next(s for s in history if s.next == ("reply",))
graph.invoke(None, past.config)

graph.get_state(config)    # latest state remains inspectable
  • Each snapshot records values, next nodes, and metadata (step, source).
  • Replay re-executes from a chosen checkpoint — debug, fork, or recover without starting over.

17 · Context vs State (Runtime)

Context

  • Supplied by the app each invocation
  • Read-only, immutable @dataclass(frozen=True)
  • Not checkpointed
  • e.g. customer name, loyalty tier

State

  • Mutable conversation data
  • Updated by tools via Command
  • Saved by the checkpointer
  • e.g. cart_items
@tool
def add_item_to_cart(item: str, runtime: ToolRuntime[ShopperContext, ShoppingState]):
    return Command(update={"cart_items": [item],
        "messages": [ToolMessage(f"Added {item}", tool_call_id=runtime.tool_call_id)]})

agent = create_agent(..., state_schema=ShoppingState,
    context_schema=ShopperContext, checkpointer=InMemorySaver())
agent.invoke({...}, config=config, context=ShopperContext("Alex", "Gold", 10))

Key Takeaways

  • Agents = model + tools + state in a loop.
  • create_agent for standard loops; StateGraph for controlled workflows.
  • State + reducers define how data merges; supersteps enable parallelism.
  • Checkpointers + thread_id give memory, persistence, and time travel.
  • Separate context (per run) from state (saved).
  • MCP standardizes tool access; LangSmith/Studio make agents observable.
